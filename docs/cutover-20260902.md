## Source-control ownership

- Frozen V1 source: branch `legacy-v1`, tag `v1-final-2026-09-02`.
- V2 source of truth: branch `main`.
- V2 source release tag: `v2.0.0-live-2026-09-02`.
- The `rac-insutech` Pages project is pinned to `legacy-v1` with all automatic
  production and preview deployments disabled. It must never deploy from `main`.
- V2 uses `.github/workflows/deploy-v2-worker.yml`. Enable it only after adding
  the scoped `CLOUDFLARE_API_TOKEN` GitHub Actions secret and setting the
  `CLOUDFLARE_DEPLOY_ENABLED` repository variable to `true`. The workflow
  deploys the Worker only; it does not create, delete, or alter production
  routes. This preserves the V1 fallback behind the two managed Worker routes.
- The deployment workflow intentionally does **not** run Supabase migrations.
  Every production migration requires a fresh data backup, review, and an
  explicit `supabase db push` release step before application deployment.
- The GitHub `CLOUDFLARE_API_TOKEN` must be a dedicated service token limited to
  this account's **Workers Scripts: Edit**, and this zone's **Workers Routes:
  Edit** and **Zone: Read** permissions. Do not use a developer OAuth token.
